# Welcome to dhpai.home

Welcome to **dhpai.home**, a one-stop portal that brings together all the pieces you need to introduce Large-Language-Model (LLM) assistants safely and productively into the Hospital Authority (HA) ecosystem.

## What does this site do?

1. **Curates Rules & Instructions**  
   Browse a growing library of ready-to-use _rules_ that steer AI assistants (e.g. GitHub Copilot, ChatGPT, Cursor) so they remain clinically safe, security-minded and HA-compliant.

2. **Lists Model Context Protocol (MCP) End-points**  
   MCP servers act as secure adapters between LLMs and internal systems like CMS, ePR, OpenShift, Jira or Grafana. Each card on the **/mcp** page explains what the integration does and shows the exact connection string or CLI snippet you can drop into your favourite AI tool.

3. **Guides IDE Integration**  
   Step-by-step walkthroughs for popular IDEs (VS Code, JetBrains, GitHub Copilot, Cursor) help you wire the MCPs, rules and `llms.txt` files directly into your coding workflow.

4. **Acts as a Knowledge Base**  
   MDX articles under **/docs** cover everything from model overviews to unit-test generation patterns and the latest HA AI-related news.

## How to navigate

| Where                | URL        | What you will find                                                                                               |
| -------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------- |

## Why it helps you

- **Single Source of Truth** - No more chasing scattered Confluence pages or e-mails; everything LLM-related for HA lives here.
- **Security & Compliance by Design** - Rules, MCPs and `llms.txt` samples are vetted to respect HA's privacy, audit and clinical-safety standards.

## DHPAI Context Engineering

### What is Context Engineering?

Think of AI assistants like having a very smart colleague who knows *general* programming - but doesn't know the *specific* rules, libraries, and patterns used in your organization. **Context Engineering** is how we teach the AI about HA's specific tools, standards, and best practices.

Imagine you're onboarding a new developer to your team. You'd give them:
- 📋 **Quick reference cards** for common tasks (like "how to create a new component")
- 📚 **Style guides** explaining coding standards across the whole project
- 👤 **A mentor** who understands their specific role (frontend dev, backend dev, etc.)

That's exactly what Context Engineering does for AI assistants! We provide three types of files that guide the AI:

### Prompt Engineering Files

These files tell the AI *how to behave* and *what standards to follow*:

| Type            | File Pattern        | What It Does (In Simple Terms)                                                                   | When You'd Use It                                                                        |
| --------------- | ------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| **Prompts**     | `*.prompt.md`       | Like asking a colleague: "Can you help me create a login form?"                                  | Quick code generation, solving a specific problem, generating documentation              |
| **Instructions**| `*.instructions.md` | Like a coding style guide: "Always use TypeScript. Never use `any`. Format dates like YYYY-MM-DD"| Making sure all code follows the same standards, enforcing best practices                |
| **Chat Modes**  | `*.chatmode.md`     | Like having different experts: a React specialist, a Java architect, a security auditor          | When you need domain-specific guidance (e.g., "talk to me like I'm doing frontend work") |

**Example in Action:**
- Without context: AI might suggest generic code using libraries HA doesn't use
- With context: AI knows to use `cms-react-ui` components and follows HA's security guidelines

### Context Knowledge Base: Teaching AI About HA Libraries

This is where it gets powerful. We don't just tell AI the *rules* - we also give it access to HA's *internal documentation and code libraries*.

#### The Challenge
Your internal wikis, component libraries, and framework docs aren't publicly available on the internet. Regular AI models have never seen them. It's like asking someone to fix your car without letting them see the owner's manual.

#### The Solution: Automated Knowledge Pipeline

We've built a system that:
1. 🔍 **Finds** all your internal documentation (GitHub wikis, component docs, API references)
2. 🤖 **Processes** them using AI to extract the most useful parts (code examples, API signatures, usage patterns)
3. 📦 **Packages** them in a format AI assistants can quickly understand
4. 🔌 **Connects** them to your IDE through MCP (Model Context Protocol) servers
5. 🔄 **Updates** automatically every day so the AI always has the latest information

#### How It Works (The Technical Flow)

```
┌─────────────────┐        ┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ GitHub Wikis    │───────>│ AI extracts key  │────>│ Organized in MCP │────>│ Your IDE/Copilot │
│ Component Docs  │        │ code snippets    │     │ for fast lookup  │     │ asks MCP for     │
│ API References  │        │ & examples       │     │                  │     │ relevant docs    │
└─────────────────┘        └──────────────────┘     └──────────────────┘     └──────────────────┘
```

**What Happens Behind the Scenes:**

| Step | What Happens | Why It Matters |
| ---- | ------------ | -------------- |
| 1.**Ingestion** | System pulls documentation from your GitHub repositories | Gets the source material |
| 2.**Processing** | AI reads through docs and extracts useful code snippets, function signatures, and examples | Makes docs easier for AI to understand quickly |
| 3.**Optimization** | Compresses information to fit in AI's "working memory" (context window) | Ensures AI can access info without getting overwhelmed |
| 4.**Storage** | Indexed and stored in MCP servers | AI can search and retrieve specific info in milliseconds |
| 5.**Maintenance** | Automatically syncs every day | AI always has the latest updates without manual work |

**Real-World Example:**

When you ask GitHub Copilot: *"Create a button using the CMS Design System"*

- ❌ **Without context**: Copilot suggests a generic HTML button or Material-UI
- ✅ **With context**: Copilot knows about `cms-react-ui`, fetches the latest Button component documentation, and generates code using the correct import and props!
